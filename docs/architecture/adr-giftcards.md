# Сертифікати

ADR: ADR-20

### ADR-20. Подарунковий сертифікат — не промокод

Спокуса зробити їх однією таблицею («і те, і те — код, що зменшує суму»)
призводить до подвійного обліку виручки. Різниця бухгалтерська, не
термінологічна:

| | Промокод | Сертифікат |
|---|---|---|
| Суть | правило знижки | передплачений інструмент |
| Гроші | не отримані | **отримані при продажу** |
| При продажу | — | **зобов'язання**, не виручка |
| Виручка | зменшується | визнається **при погашенні** |
| Де застосовується | `pricing` | **`PaymentProvider`** |
| Екземплярність | код → багато покупців | код → один баланс |
| Витрачання | цілком | частинами |

Наслідки, які ламаються найлегше:

1. **Продаж сертифіката не є виручкою.** Звіт виручки виключає
   `order_items` з `product.kind = 'gift_card'`. Інакше задвоєння: спершу
   при продажу сертифіката, потім при купівлі за нього.
2. **Сертифікат — спосіб оплати.** Замовлення може бути оплачене частково
   ним, частково карткою, тому `captured_total` збирається з кількох
   `payment_attempts`.
3. **Погашення завжди під `SELECT ... FOR UPDATE`** на `gift_cards`. Без
   цього два паралельні замовлення витратять той самий баланс — той самий
   клас проблеми, що з резервуванням залишків.
4. **Баланс денормалізований, істина — журнал.** `gift_card_transactions`
   append-only; воркер щодня звіряє й алертить.
5. **Промокодом не можна купити сертифікат, сертифікатом — інший
   сертифікат.** Обидва — схеми виведення грошей.
6. **Повернення товару, оплаченого сертифікатом, іде на сертифікат.**
   Інакше сертифікат стає способом вивести гроші на картку.
7. Код зберігається як хеш, високої ентропії, не послідовний. Це гроші на
   пред'явника.

Деталі — `GIFT_CARDS.md`. Специфікація промокодів — `PROMO_CODES.md`.
