## Чого НЕ робимо у v1

Бонусна програма й реферали. Стековані промокоди (прапорець `stackable` у
схемі є, логіка комбінування — ні). Персональні одноразові коди на клієнта.
Bulk-генерація кампаній. Мультивалютність і міжнародна доставка. Вигрузки
на Rozetka та Prom. PWA і мобільний застосунок — **але auth і DTO-шар готові**, бо питання №4
підтверджене. Публічний API. A/B-тести. Живий чат — замінити кнопками
Telegram і Viber. Складський облік з приходами й постачальниками.
Рекомендації на ML. `cacheComponents` / PPR — окрема міграція після запуску
(ADR-9). React Compiler — тільки якщо профайлер покаже проблему.

## Тестування

**Головне виправлення:** тести конкурентності на моках нічого не доводять.
Порядок блокувань у реальних транзакціях інший, unique violation перериває
транзакцію цілком, а ручні міграції (тригер `search_vector`, складені FK)
на моках не виконуються взагалі. `drizzle-kit check` перевіряє узгодженість
історії згенерованих міграцій — **не** виконуваність SQL і не дрейф
продакшн-БД. CI при цьому лишається зеленим.

| Що | Чим | Покриття |
|---|---|---|
| `packages/core` — ціни, розподіл знижок, переходи статусів, `bra-size` | Vitest unit | Високе. Тут баг коштує грошей |
| **Конкурентність** | Інтеграційний suite на **реальному Postgres 16** з розширеннями, кількома незалежними з\'єднаннями і бар\'єрами синхронізації | Остання одиниця; останнє використання промокоду; expiry проти оплати; два паралельні повернення; два вебхуки різних типів |
| **Відновлення після падіння** | Той самий suite з перезапуском процесу в критичних точках | Падіння між вставкою події й комітом; падіння до публікації outbox |
| Вебхуки платіжок | Записані **реальні** payload\'и провайдерів як фікстури | Кожен статус, невалідний підпис, дубль, порушений порядок, зміна непідписаних полів |
| Клієнти НП і Укрпошти | `msw` + один реальний smoke на staging із тестовою накладною **і її скасуванням** | Основні методи, `unknown` після таймауту |
| Міграції | CI піднімає **порожню** БД і виконує всі міграції; окремо — оновлення копії попередньої схеми | Виконуваність, не лише узгодженість |
| Серіалізація по ролях | Перевірка **фактичної** відповіді для кожної ролі | `cost_price`, `unit_cost_snapshot`, `audit_log.diff` не витікають |
| Checkout happy path і помилка залишку | Playwright | У CI на кожен PR |
| Генерація номерів | Vitest на межах `99999/100000`, `999999/1000000` | `lpad` обрізає довші значення |

**Баг у грошах або залишках спершу відтворюється тестом, потім фіксується.**
