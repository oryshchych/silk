## Фаза 3 — Оплати (1–1.5 тижня)

**Мета:** гроші приходять, статус змінюється, залишки не течуть.

**Обсяг:**
- `PaymentProvider` у `packages/payments`.
- **Plata by mono** перший: створення інвойсу, вебхук з перевіркою підпису публічним ключем (кешувати), мапінг статусів.
- **WayForPay** другий: HMAC_MD5 підпис, і головне — коректно підписана відповідь на колбек, інакше ретраї годинами.
- COD з лімітом суми; банківський переказ.
- **Подарункові сертифікати — НЕ реалізуються** (заборонені на 2-й групі,
  питання №2). Лише шви з `GIFT_CARDS.md` §0: оплата як набір спроб,
  refund за спробою, відмова checkout для `gift_card`.
- `payment_events` з `UNIQUE(provider, external_id)`.
- Життєвий цикл замовлення, `order_status_history`.
- Резервація → реальне списання при `paid`; повернення на склад при `failed` / `cancelled` / `expired`.
- Повернення коштів, повні й часткові.
- **`FiscalProvider` + реалізація Checkbox** (питання №1, ADR-16): картка —
  чек після вебхука; COD — чек на товар при передачі на пошту, форма оплати
  «Післяплата»; переказ на IBAN — `not_required`. Чек повернення посилається
  на первинний. Live-активація — після акаунта Checkbox.

**Критерії приймання:**
- [ ] `paid` встановлюється **лише** вебхуком; GET на `/order/success` статус не змінює
- [ ] Той самий вебхук ×5 обробляється один раз
- [ ] Два **різні** івенти по одному замовленню одночасно (`authorized` + `paid`)
      не списують товар двічі — рядковий лок на `orders` працює (ADR-4)
- [ ] «Не вистачило коштів → інша карта» створює другу `payment_attempts`,
      а НЕ друге замовлення, і не резервує товар удруге (ADR-11)
- [ ] Падіння `FiscalProvider` (мокнути 503) не відкочує підтвердження оплати;
      замовлення отримує `fiscal_status = 'failed'` і алерт (ADR-16)
- [ ] Невалідний підпис → 4xx + запис у **`webhook_quarantine`**, НЕ в
      `payment_events`. Перевірити явно: спершу надіслати сміття з правильним
      `invoiceId`, потім справжній вебхук — справжній мусить застосуватись
      (раніше він відкидався як дубль, бо сміття займало ключ)
- [ ] Вебхук, що прийшов **раніше** за redirect, обробляється коректно — перевірити явно
- [ ] Скасування повертає залишки, сума по варіанту сходиться
- [ ] Часткове повернення видно в історії
- [ ] Sandbox-платіж end-to-end на staging для обох провайдерів
- [ ] Кожен транзакційний лист перевірений у **темному режимі** Gmail (iOS і web)
      та Outlook: текст читається, логотип видно
- [ ] Чек: картка → `fiscal_documents` після вебхука; COD → при передачі на
      пошту з формою «Післяплата»; переказ → `not_required` (sandbox Checkbox)
- [ ] Чек повернення містить фіскальний номер первинного чека
- [ ] Шов: прямий виклик checkout у `core` з `kind='gift_card'` або
      провайдером `gift_card` → помилка, замовлення не створено
- [ ] Шов: дві `payment_attempts` різними провайдерами → `captured_total` = сума;
      refund іде на провайдера своєї спроби
- [ ] `grep` по `.next/static` не знаходить жодного секрету
