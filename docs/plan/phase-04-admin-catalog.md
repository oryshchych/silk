## Фаза 4 — Адмінка: доступи й каталог (2 тижні)

**Мета:** контент-менеджер наповнює магазин без розробника.

**Обсяг:**
- Auth.js: email+пароль, TOTP обов'язковий для `owner` і `admin`.
  Якщо питання №4 = «мобільний реалістичний» — тут же bearer-токени з ротацією refresh.
- Роли `owner` / `admin` / `manager` / `content`. Перевірка в `proxy.ts` **і** в кожному server action.
- `SECURITY.md`: таблиця «мутація → хто може → де перевіряється». Створюється тут і оновлюється разом з кодом.
- Layout адмінки, серверна пагінація й фільтри.
- Товари: список з bulk-діями, редактор (основне, ціни, варіанти, медіа, SEO з живим превʼю сніпета, зв'язки).
- Генератор матриці варіантів: кольори × розміри → комбінації, inline-редагування, масове встановлення залишків.
- Медіа: R2, `sharp` → WebP + AVIF у трьох розмірах, drag&drop, alt UK/EN з попередженням про порожні, прив'язка до кольору. `images.remotePatterns` для домену R2.
- Категорії: дерево з drag&drop, SEO-поля.
- Розміри, кольори, атрибути.
- Склад: усі варіанти, фільтр «закінчується», історія змін.
- Імпорт/експорт CSV та XLSX: превʼю, валідація по рядках, режим «оновити за SKU».
- `audit_log` на всі мутації.
- Інвалідація: `updateTag` для адмінського в'ю + `revalidateTag(tag, 'max')` для вітрини (ADR-8).

**Критерії приймання:**
- [ ] Товар 3 кольори × 12 розмірів створюється й наповнюється за < 10 хвилин
- [ ] Роль `content` отримує 403 на зміну ціни — і в UI, **і** при прямому POST на server action
- [ ] Фото 4000px віддається на PDP як WebP ≤ 150 КБ
- [ ] Імпорт 100 рядків з трьома битими: 97 імпортовано, три помилки з номерами рядків
- [ ] Зміна slug створює 301 автоматично
- [ ] Кожна мутація має запис в `audit_log` з автором і diff
- [ ] Правка товару видна в адмінці **негайно**, на вітрині — протягом ревалідації
- [ ] Перемикач теми в адмінці працює без flash при перезавантаженні
- [ ] Тема адмінки **не** впливає на HTML вітрини й не фрагментує ISR-кеш
- [ ] Зміна одного товару не інвалідує весь каталог
- [ ] `SECURITY.md` заповнений і збігається з кодом
