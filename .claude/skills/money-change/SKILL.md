# money-change

Баг у грошах або залишках **спершу відтворюється тестом, потім фіксується**
(AGENTS.md §2.9). Пройди кожен пункт і для кожного назви, чим перевірено.

## Чек-лист

- [ ] **Суми — `Money`** (`@store/shared/money`), не `number`. Арифметика лише через
      `add` / `subtract` / `multiply` / `percentOf` / `allocate`; лінт
      `money/no-arithmetic` зелений.
- [ ] **Округлення — один раз, у pricing**, з явним режимом (`percentOf(..., 'half-up')`).
      Розподіл знижки — `allocate` (largest remainder, ADR-15), не «залишок на останню».
- [ ] **Транзакція — перший параметр** (`tx: Tx`), а не глобальний `db` (AGENTS.md §4b.1).
      Перевірено навмисною помилкою після кожного кроку: відкотилось усе.
- [ ] **Залишки — атомарний умовний `UPDATE`** (ADR-3), ніколи SELECT → перевірка → UPDATE.
      Семантика ADR-18: резерв до `shipped`, склад зменшується лише при `shipped`.
- [ ] **Інваріанти сум**: `subtotal = Σ(line_total + line_discount)`,
      `discount_total = Σ line_discount`, `total = subtotal − discount + shipping + adjustment`.
- [ ] **Фінансовий статус** змінює лише підтверджене серверне джерело (ADR-4): вебхук,
      `getPaymentStatus`, підтверджене надходження. Redirect — ніколи.
- [ ] **Подія + фінстан + склад + історія + outbox — одна транзакція** (AGENTS.md §5b).
- [ ] **Локи** беруться в тому самому порядку в усіх шляхах (замовлення → варіанти за `id`).
- [ ] **Тест на паралельний виклик** з окремими з'єднаннями й бар'єром, не з одного пулу.
- [ ] Покриття `pricing` / `inventory` ≥ 95% (`pnpm test:coverage`).
- [ ] Сертифікати не продаються й не приймаються (GIFT_CARDS.md §0): шви на місці.

Наприкінці — субагент **`money-reviewer`**.
